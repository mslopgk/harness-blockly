- 실행 시 **소스 전문을 더 이상 실행 출력에 찍지 않는다**. `[Shell] Code:\n${code}` → `[Shell] 프로그램 N줄 실행` (`src/App.jsx` L939). 중등은 블록 전용 수업이라 파이썬이 보이면 안 된다는 이유.

### 2.6 예제 — 차시별 3단계
중등 2차시 + 고등 3차시, 각 3단계 = **15개**가 갤러리에 등록된다(기존 5개 완성본 → 15개 단계 파일).
각 단계는 앞 단계를 포함하므로 학생이 그 파일 하나만 열어도 처음부터 끝까지 돌아간다.

| 차시 | ① | ② | ③ |
|---|---|---|---|
| 중등1 AI 분리수거 | `m1_1_찾기.py` (로봇 없음) | `m1_2_잡기.py` | `m1_3_놓기.py` |
| 중등2 가위바위보 | `m2_1_손보기.py` | `m2_2_응수하기.py` | `m2_3_대전하기.py` |
| 고등1 자연어 제어 | `h1_1_알아듣기.py` (import 없음) | `h1_2_움직이기.py` | `h1_3_대화하기.py` |
| 고등2 제스처 텔레옵 | `h2_1_배우기.py` | `h2_2_움직이기.py` | `h2_3_조종하기.py` |
| 고등3 비전 자율주행 | `h3_1_배우기.py` | `h3_2_고르기.py` | `h3_3_달리기.py` |

- 로봇팔을 쓰는 예제 **12개 전부**가 마지막에 `팔.pump_off()` 로 끝난다(전수 확인함). 주행로봇(h3)은 펌프가 없어 `차.stop()` 으로 대체.
- 기존 완성본 5개 + `*_blocks.py` 2개는 디스크에 남지만 갤러리 목록에는 싣지 않는다.

### 2.7 AI 도우미가 화면을 "본다"
앱이 `POST /api/ui-state` 로 500ms 디바운스 상태를 보내고 서버가 워크스페이스의 `.blockpy/state.json` 에 1초 스로틀로 떨군다.
AI 도우미는 `cat .blockpy/state.json` 으로 지금 탭·열린 파일·실행 여부·실행 출력 마지막 20줄·블록 수·로봇 연결·TM 상태·보정 여부를 읽는다.
근거: `src/App.jsx` L1576~1628(`uiStateRef` L1582), `server.js` `scheduleUiStateWrite`, `agent-context/AGENTS.md` "지금 화면에서 무슨 일이 일어나는지 먼저 확인하라".

### 3.4 robotvision ↔ affineCalib 의 관계 (계약 4의 핵심)

두 파일은 **같은 아핀 행렬 M 을 같은 배치로** 다뤄야 한다. 확인했고 일치한다.

```
M = [[a, b, c],
     [d, e, f]]
x = a*u + b*v + c
y = d*u + e*v + f
```

- **추정(JS)**: `src/utils/affineCalib.js` `estimateAffine(pairs)`
  - `pairs = [[[u,v],[x,y]], …]`, 각 축을 정규방정식 `AᵀA p = Aᵀt` 로 따로 푼다(행 = `[u, v, 1]`).
  - 3×3 은 부분피벗 가우스-조던(`solve3`). 대응점 3개 미만 또는 거의 한 직선이면(`isDegenerate`: `|det(AᵀA)| ≤ 1e-9·trace³`) 한국어 메시지로 throw.
  - `reprojectionError(M, pairs)` 가 mm 단위 평균/최대 재투영 오차를 돌려준다(패널에 표시).
- **저장**: `RobotCalibrate.jsx` `saveSolved()` 가 localStorage(`saveCalib`)와 **동시에** `pushCalibToBackend()` 로 `POST /api/robot/calib` 를 친다. 본문에 `version, measured, M, pairs, observation, markZ`. 백엔드 실패는 전부 무시(패널은 백엔드 없이도 동작해야 하므로). "기본값으로 되돌리기" 도 백엔드로 함께 되돌린다 — 안 그러면 화면과 파이썬이 서로 다른 보정을 쓴다.
- **적용(Python)**: `runtime/robotvision.py`
  - `robot_calib.json` 을 **cwd 우선, 그다음 `BLOCKPY_WORKSPACE`** 순으로 찾는다. `/api/run-python` 과 PTY 모두 cwd 가 워크스페이스라 정상 경로에서는 cwd 로 맞는다.
  - mtime 캐시(파일이 바뀌면 다시 읽음). `measured === false` 면 미측정 취급. 깨진 JSON 도 미측정 취급.
  - `to_robot()` 은 `applyAffine` 과 동일한 곱셈 순서(행 = 출력축, 열 = `[u, v, 1]`).
  - 미보정이면 `RuntimeError("자리 맞추기를 먼저 해 주세요. 로봇 패널 → 자리 맞추기 …")`.
  - `find_object(frame)` 은 cv2 만 쓴다: grayscale → GaussianBlur(5) → **Otsu 이진화**(흰 영역이 화면 절반을 넘으면 반전) → MORPH_OPEN(타원 5×5) → `RETR_EXTERNAL` 외곽선 → 면적이 `max(200, 0.2%)`~`90%` 인 것 중 최대 → 모멘트 무게중심 `(u, v)` 정수 반환. 못 찾으면 `None`. OpenCV 3/4 반환 개수 차이는 `found[-2]` 로 흡수.
- **블록 등록**: `src/data/visionSpecs.json` 이 `tmSpecs.json` 형식을 그대로 따르고, `App.jsx` 가 `import.meta.glob('./data/vision*.json', {eager:true})` 로 집어 builtin 스펙에 합친다. 파일이 없으면 빈 목록이 되어 빌드가 깨지지 않는다(담당 분리 때문에 정적 import 를 피한 것).

### 3.5 TeachableMachine.jsx — 티처블머신 판박이 재작성

`src/components/TeachableMachine.jsx` (692줄). 화면은 구글 티처블머신 "이미지 프로젝트" 구조 그대로,
**이름표(클래스) 열 → 학습 → 미리보기** 3열. 우리 것은 한국어 용어와 `.npz` 저장 방식뿐이다.

- 샘플 하나 = `{ embedding: tf.Tensor2D[1,D], jpeg: dataURL }`.
  - `embedding` — 브라우저 TF.js MobileNet. **패널 안 즉시 학습·라이브 미리보기 전용(피드백용)**.
  - `jpeg` — 원본 프레임(긴 변 224 로 축소, q=0.8). **저장 시 백엔드로 보낸다**.
- **저장은 브라우저 head 를 내보내지 않는다.** TF.js MobileNet 임베딩과 Keras MobileNetV2 임베딩은 공간이 달라 파이썬 `tm.load_model` 이 그 가중치를 재사용할 수 없다(설계문서에 코사인 0.79 로 실측 기록). 그래서 프레임을 `POST /api/tm/train` 으로 보내 **파이썬이 다시 학습**하고 `<이름>.npz` 를 만든다. 티처블머신의 "Export Model" 은 흉내내지 않는다.
- 상수: `CAPTURE_MS=100`, `CAPTURE_MAX_SIDE=224`, `MAX_SAMPLES=600`(백엔드 상한과 동일), `MAX_THUMBS=60`(600장을 다 그리면 메모리가 터진다), `DEF_EPOCHS=30`/`DEF_BATCH=16`/`DEF_LR=0.001`.
- `onStateChange(s)` prop 으로 `{labels, samples[], trained, model?}` 를 **값이 실제로 바뀔 때만** 올린다(App 이 이 콜백으로 네트워크 요청을 하므로 렌더마다 부르면 안 된다). `model` 은 저장 성공 후에만 들어간다.
- 텐서 수명: 재학습·언마운트 시 `disposeSamples`/head dispose, 캡처 타이머·RAF 정리.
- 웹캠 미리보기 박스 높이 고정 — 수집 중 버튼이 커서 밑에서 빠져나가 수집이 끊기던 버그 방지.
- **계약이 못 박은 test id 는 전부 보존**: `#tm-classname-N` `#tm-count-N` `#tm-capture-N` `#tm-add-class` `#tm-train` `#tm-trained` `#tm-filename` `#tm-save` `#tm-save-status` `#tm-preview-label` `#tm-status` `#tm-classes`.

### 4.6 병합 시 부딪힐 구조적 문제

1. **예제 이중 등록 지점.** 새 예제를 추가하려면 `src/examples/lessons.js` 의 `LESSON_EXAMPLES` 와 `server.js` L280~289 의 하드코딩 `NAMES` 배열을 **둘 다** 고쳐야 한다. 후자를 빠뜨리면 워크스페이스에 복사되지 않아 AI 도우미가 그 예제를 못 본다(실제로 `*_blocks.py` 가 빠져 같은 사고가 있었다).
2. **`ROBOT_BRIDGE` 경로만 `genBase()` 를 안 쓴다.** `server.js` L845 가 `path.join(__dirname, 'scripts', 'robot_bridge.py')` 인데 `scripts/` 는 `build.files` 에도 `asarUnpack` 에도 없다. 패키징본에서 로봇 API 가 동작하는지는 **실기 확인이 필요**하다.
3. **`/api/run-python` 만 다른 규약을 쓴다.** 신규 spawn 경로는 전부 `PYTHONUTF8` + 타임아웃 + `killTree` 인데, `run-python` 은 `PYTHONUTF8` 없음 · 타임아웃 없음 · abort 시 `child.kill()`(트리 아님)이다. 자식이 손자를 남기면 고아가 된다.
4. **`test_lessons` 정규식이 중복 주석에 의존한다.** `tests/example_lessons.spec.js` 가 `/\[H3\]/` 로 검사하는데 `h3_3_달리기.py` 의 1행은 `# [H3-③] …`(매치 안 됨)이고 2행에 남은 옛 헤더 `# [H3] …` 가 매치를 살린다. 주석을 정리하면 테스트가 깨진다.
5. **`affineCalib.js` 헤더 주석이 낡았다.** "레포 util 관례대로 `module.exports`" 라고 적혀 있으나 실제로는 ESM `export {}` 다.
6. **패키징 재현 불가.** `python-embed/`, `opencode-embed/`, `vendor-installers/` 가 전부 gitignore 인데 자동 생성기가 있는 것은 `python-embed` 뿐이고, 그마저 현재 실물과 어긋난다 — `scripts/bundle-python.py` 의 `PKGS` 는 `numpy, opencv-python, pillow, jedi, pyserial` 인데 실제 `site-packages` 에는 `dobotkit 0.2.0`·`websockets 17.0.1` 이 있고 `pillow`/`jedi`/`pyserial` 이 없다(수동 pip 조작이 섞였다). 출처 불명의 `_blockpy_pythonpath.pth` 도 있다. **클론만으로 `npm run dist` 를 성공시킬 수 없다.**
7. **3자 재배포 라이선스.** `vendor-installers/VERSION.txt` 가 스스로 "Dobot 사의 제품이며 우리 저작물이 아니다. 재배포 조건은 Dobot 정책을 따른다" 고 적고 있다. 400MB 설치본 동봉은 인계 전 확인이 필요하다.

### 4.7 보안

- **`WS /api/terminal` 에 인증이 없다.** 방어는 둘뿐이다 — `app.listen(port, '127.0.0.1')` 루프백 바인드와 upgrade 훅의 `isLoopbackHost(req)` Host 헤더 검사. 토큰·Origin·쿠키 검사는 없다. 이 소켓은 워크스페이스를 cwd 로 하는 **임의 셸**을 준다. 로컬 교실용 전제에서는 기존 `/api/run-python` 과 같은 수준의 노출이지만, 원격 접근 시나리오가 생기면 즉시 막아야 한다.
- **비밀은 커밋되지 않았다.** `electron/bundled-keys.cjs` 는 존재하고 `.gitignore:38` 로 무시되며 `git ls-files` 에 없다(커밋 이력 0). 없어도 앱은 정상 부팅한다(`main.cjs` try/catch). **빌드 머신에만 있으므로 인계 시 별도 전달 경로가 필요하다.**

## 6. 알려진 한계 / 남은 일

### 미완 (코드가 있으나 배선되지 않음)
1. **`electron/setup/` 온라인 설치 매니페스트** — `manifest.json` 도 `download.cjs` 도 **호출하는 코드가 없다**. 설계+유틸까지만 된 WIP. 현재 설치본은 여전히 667MB 전량 동봉이다.
2. **`/api/tm/prepare-status` 에 소비자가 없다.** tensorflow 자동 설치(계약 5)는 서버에 구현돼 있고 상태 머신·로그 링버퍼·안내문(`AI 학습 준비물을 내려받는 중입니다. 몇 분 걸립니다`)까지 있지만, **프런트도 AGENTS.md 도 이 엔드포인트를 부르지 않는다**(저장소 전체에서 `prepare-status` 가 `server.js` 에만 등장). 실제 화면에서는 TM 패널 저장 버튼이 `파이썬으로 학습 중… (수십 초 걸릴 수 있어요)` 를 띄운 채 **최대 30분간 아무 진행 표시 없이 멈춰 있게 된다.** 계약 5 의 "진행 상황을 스트리밍한다" 는 서버 반쪽만 충족됐다.
3. **`/api/cameras` 는 프런트가 부르지 않는다.** 설계상 AI 도우미가 `curl` 로 쓰는 것이라 의도된 것이지만, AGENTS.md 는 포트를 "`.blockpy/state.json` 이나 실행 출력에서 확인" 하라고만 하는데 **`state.json` 에 포트 필드가 없다**. AI 가 실제로 이 API 를 부를 수 있는지는 검증되지 않았다.
4. **`state.json` 의 `exit_code`** — 계약 1 에 있으나 `/api/run-python` 이 종료 코드를 따로 주지 않아 넣지 않았다(코드 주석에 명시). `output_tail` 의 `[exit 0]` 글자로만 알 수 있다.
5. **`visionSpecs.json` 에 생성기가 없다.** `robotSpecs`/`tmSpecs` 는 `scripts/gen-*.cjs` 가 있는데 이것만 손으로 썼다. `runtime/robotvision.py` 시그니처와 어긋나도 잡아줄 것이 없다.

- 패키징본(`.exe`)에서 `scripts/robot_bridge.py` 가 해석되는지 (§4.6-2).
- 브라우저 TM 패널의 미리보기와 파이썬 `.npz` 예측이 실제로 얼마나 일치하는지 — 설계상 다른 임베딩이므로 **패널에서 잘 맞던 것이 코드에서는 다를 수 있다**. 학생 혼란의 잠재 원인.
- 3단계 예제의 블록 변환 — `tests/examples_gallery_blocks.spec.js` 는 `snippets.js` 의 인라인 스니펫만 순회하고 **`lessons.js` 파일 예제는 커버하지 않는다**. 15개 새 파일이 블록으로 깨끗이 변환되는지 자동 게이트가 없다.

### 단계별 누적성 — 정확히는
계약 7 은 "각 단계는 앞 단계를 포함한다" 였다. 실측 결과 **①→② 는 순수 append**(삭제된 줄이 전부 주석)지만,
**②→③ 은 순수 append 가 아니다** — ②의 "한 번만 실행" 코드가 ③에서 `for` 루프 본문으로 들여쓰기되어 재배치된다
(`m2_2`→`m2_3` 에서 실행 코드 19줄이 이동, `h2_2`→`h2_3` 도 동일). **의미상 누적은 맞고 텍스트상 누적은 아니다.**
