# 카메라↔로봇 캘리브레이션 UI — 설계 (Design)

- 날짜: 2026-07-16
- 대상: BlockPy 플랫폼 (blockly프로젝트) 프론트엔드
- 관련 수업: 중등1차시 M1 색상분류/분리수거 (카메라 픽셀 → 로봇 mm 좌표 매핑)

## 목표

중등1차시에서 필요한 카메라↔로봇팔 좌표 캘리브레이션을, 현재의 번거로운 방식
(화면 클릭 + 로봇 수동 조깅을 3점 이상 반복 → 아핀 추정)에서 **거의 무작업**으로 바꾼다.

- **기본**: 저장된 **고정 캘리값 1개**를 자동 로드 → 학생은 캘리브레이션을 하지 않는다.
- **폴백(수동 재보정, 드묾)**: 세팅이 어긋났을 때만, **조깅 없이** 재보정한다
  (로봇이 알려진 프리셋으로 스스로 이동 → 화면에서 엔드이펙터 클릭 → 아핀 풀이).

리그(카메라·매트·로봇 배치)는 **하나로 고정**이라, 캘리값 하나로 전 교실을 커버한다.

## 원칙 / 제약

- **블록 코어 무수정** (`irBlocks.js`/`irToBlockly.js`/`blocklyToIr.js`/`irToolbox.js` 불변) — [[ADR: python-first-extension]] 정신 유지.
- **프론트 전용 구현**: 로봇 연결 라이브러리(dobotkit)가 **미확정**이므로, 로봇을 실제로
  움직이는 부분만 훅으로 남기고 나머지는 지금 다 프론트로 만든다.
- **가짜 기본값 금지(안전)**: 실측되지 않은 캘리 행렬을 지어내 박아두지 않는다. 잘못된
  행렬은 로봇이 엉뚱한 좌표를 찍어 충돌시킬 수 있다. 실측 전에는 "미측정" 상태로 둔다.

## 동작 흐름

1. **마운트 시**: 저장된 캘리값 로드.
   - 있으면 → "고정 캘리브레이션 사용 중 · 재투영 오차 X.Xmm".
   - 없으면(미측정) → "최초 1회 재보정 필요" 안내.
2. **재보정(접근 1)**: "재보정 시작" →
   - 프리셋 `i = 0…N-1`(기본 4점)에 대해:
     1. `[훅:dobotkit]` 로봇을 `preset[i]`(x,y,z)로 이동 — **현재 스텁**(미연결 배지 표시).
     2. 웹캠 화면에서 엔드이펙터를 클릭 → `(pixel[i], preset[i])` 대응쌍 기록.
     3. 다음 점.
   - N점 후: **아핀 2×3 풀이(JS 최소제곱)** → 재투영 오차 리포트 → "저장".
   - "이전/다음/취소/초기화" 지원. `<3점` 또는 거의 일직선이면 풀이 거부.
3. **소비(백엔드 영역, 훅)**: 저장된 캘리값을 학생 파이썬 프로그램이 읽어 픽셀→로봇
   변환에 쓴다. 이 소비부(및 로봇 이동)는 dobotkit 확정 후 배선.

## 캘리값 저장 / 기본값(seed) 전략

- 형식: 아핀 행렬 M(2×3) + 등록 대응쌍 + 재투영오차 + 프리셋. JSON.
- 저장 위치(프론트): `localStorage['blockpy.robotCalib.v1']`.
- **seed 기본값**: `src/data/robotCalib.default.json` — 앱 동봉 기본 캘리값.
  - **지금**: `{ "M": null, "measured": false, ... }` (미측정 — 값 없음).
  - **하드웨어+dobotkit 확정 후**: 실제 리그에서 재보정 1회 → 그 결과 M을 이 파일에
    끼워 넣는다(코드 변경 없이 값만 교체). 이후 학생 PC는 첫 실행부터 재보정 불필요.
- 로드 우선순위: localStorage(사용자가 재보정해 저장한 값) > seed default > 미측정.

## 컴포넌트 / 파일

- **신규** `src/utils/affineCalib.js` — 순수함수. `estimateAffine(pairs) → M(2×3)`(최소제곱,
  파이썬 `estimate_affine` 미러), `applyAffine(M, [px,py]) → [x,y]`, `isDegenerate(pairs)`
  (일직선 검사), `reprojectionError(M, pairs)`. Blockly/DOM 의존 없음 → 단위테스트 용이.
- **신규** `src/data/robotCalib.default.json` — seed 기본값(현재 미측정).
- **신규** `src/components/RobotCalibrate.jsx` — 캘리브 패널 + 재보정 상태기계.
  - props: `onMoveToPreset(preset) → Promise` (기본값 = 스텁: 즉시 resolve + "미연결").
  - 내부: 웹캠(getUserMedia) 뷰, 캔버스/오버레이 클릭 캡처, 흐름(idle→capturing i→solved),
    affineCalib 호출, localStorage 저장/로드.
- **수정** `src/App.jsx` — Robot 탭 패널에 `<RobotCalibrate/>`를 `<RobotConnect/>` 아래로 추가.
  (탭 구조·기존 컴포넌트는 그대로. 3~4줄 추가.)

## 프리셋 좌표

- 기본 4점(로봇 작업평면 mm), M1 커리큘럼 `CALIB_PRESETS` 값을 출발점으로:
  `(200,-80) (200,80) (300,80) (300,-80)`. **실측 플레이스홀더** — 카메라 화각 안에 4점이
  다 보이는지는 하드웨어 확정 후 검증. 컴포넌트 상단 상수 1곳에 모아둔다.

## 에러 처리

- 웹캠 없음/권한 거부 → 안내 문구 + 클릭 캡처 비활성(재보정 불가, 기본 로드는 유지).
- 대응쌍 <3 또는 일직선(`isDegenerate`) → 풀이 거부 + "점을 더 넓게 다시 찍으세요".
- `onMoveToPreset` 미배선(스텁) → 흐름은 진행하되 "로봇 자동이동 미연결(dobotkit 대기)"
  배지. 로봇이 실제로 안 움직이므로 이 상태의 재보정 결과는 신뢰 불가임을 명시.
- 저장 실패(localStorage 불가) → 경고, 세션 메모리로만 유지.

## 테스트

- **단위(순수 JS)**: `affineCalib.js` — 알려진 아핀(예: x=0.5u+100, y=−0.4v+180)으로 합성
  4점 → `estimateAffine` 복원 오차≈0, `applyAffine` 왕복, 일직선 4점 → `isDegenerate=true`.
- **Playwright**: 패널 렌더, 저장값 없을 때 "재보정 필요" 표시, 재보정 스텝 진행(스텁 이동),
  가짜 미디어스트림(`--use-fake-device-for-media-stream`)으로 클릭 4회 기록 → "풀기 & 저장"
  → 상태가 "사용 중 · 오차 …"로 바뀜.

## 범위 밖(YAGNI / 후속)

- 호모그래피(원근) — M1은 위에서 내려다보는 평면이라 아핀으로 충분. 필요 시 후속.
- 오프셋 미세조정(A안) — 이번 범위 제외(B 채택). 후속으로 얹기 가능.
- 로봇 이동·캘리값 소비의 실제 배선 — dobotkit 확정 후 별도 작업.
