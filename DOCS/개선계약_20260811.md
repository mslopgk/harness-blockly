## 계약 1 — 앱 실시간 상태 파일 (6번 항목)

**A**: 프런트가 보낸 상태를 워크스페이스 파일로 떨군다.

- `POST /api/ui-state` — 본문을 그대로 받아 `<WORKSPACE_DIR>/.blockpy/state.json` 에 **원자적으로** 쓴다
  (임시파일 → rename). 200 `{ok:true}`. 실패해도 앱을 죽이지 마라.
- `GET /api/ui-state` — 마지막 상태를 그대로 돌려준다(없으면 `{}`).
- 쓰기는 **최대 1초에 한 번**으로 스로틀. 파일은 UTF-8, 사람이 읽을 수 있게 들여쓰기 2.

**C**: 상태가 바뀔 때마다 `POST /api/ui-state` 로 보낸다(디바운스 500ms, 실패는 무시).
보낼 내용 — **이 키 이름 그대로**:

```json
{
  "at": "2026-08-11T12:34:56.789Z",
  "tab": "블록 작업실" | "파이썬 코드",
  "file": "main.py",
  "running": false,
  "blocks": 21,
  "output_tail": ["마지막 줄", "…최대 20줄"],
  "exit_code": 0,
  "robot": { "connected": true, "device": "Magician Lite" },
  "tm": { "labels": ["캔","플라스틱"], "samples": [31, 28], "trained": true, "model": "분리수거.npz" },
  "calib": { "ready": true }
}
```

모르는 값은 **넣지 마라**(지어내지 말 것). `output_tail` 은 실행 출력 마지막 20줄.

## 계약 2 — 카메라 (3번 항목)

**A**: `GET /api/cameras` — 파이썬으로 인덱스 0~3 을 열어 보고 **실제로 열리는 것만** 돌려준다.
```json
{ "available": [0], "checked": [0,1,2,3], "note": "TM 패널이 웹캠을 쓰고 있으면 목록이 비거나 줄 수 있다" }
```
타임아웃 15초. 실패 시 500 대신 `{"available":[], "error":"…"}` 로 200.

## 계약 3 — 안전 정지 (1번 항목)

**A**: `POST /api/robot/safe-stop` — 파이썬 한 조각을 돌려 `dobotkit.MagicianLite()` 연결 후
`pump_off()` 를 부른다(그리고 가능하면 `grip(False)`). 로봇이 없으면 조용히 `{ok:false, reason:"…"}`.
**절대 예외로 서버를 죽이지 마라.** 타임아웃 20초.

**C**: 상단바 **정지** 버튼이 실행 중단 뒤 이 API 를 **항상** 호출한다(결과는 실행 출력에 한 줄로 알림).

## 계약 4 — 캘리브레이션 내보내기 (8번 항목)

**A**: `POST /api/robot/calib` — 본문을 `<WORKSPACE_DIR>/robot_calib.json` 에 쓴다.
`GET /api/robot/calib` — 그 파일을 돌려준다(없으면 `{measured:false}`).

**C**: `RobotCalibrate.jsx` 가 보정을 저장할 때 localStorage 와 **함께** 이 API 로도 보낸다.
형식은 지금 localStorage 에 넣는 것과 같게 하되 `observation`·`markZ` 도 포함한다.

**D**: `runtime/robotvision.py` 를 새로 만든다. 학생 블록에서 쓸 수 있게 **함수는 3개만**:

```python
is_ready() -> bool                  # robot_calib.json 이 있고 M 이 측정됐나
to_robot(u, v) -> (x, y)            # 카메라 픽셀 → 로봇 좌표 (아핀 M 적용)
find_object(frame) -> (u, v) or None  # 화면에서 가장 큰 물체의 중심 픽셀
```

- `robot_calib.json` 은 **워크스페이스**(=실행 폴더)에서 찾는다. 없으면 `is_ready()` 가 False,
  `to_robot` 은 친절한 한국어 RuntimeError.
- `find_object` 는 cv2 만 쓴다(배경과 다른 가장 큰 덩어리의 무게중심). 못 찾으면 None.
- 아핀 적용식은 `src/utils/affineCalib.js` 의 `M` 배치와 **정확히 같아야** 한다. 그 파일을 읽고 맞춰라.
- `src/data/visionSpecs.json` 도 만들어라 — 형식은 `src/data/tmSpecs.json` 을 그대로 본떠라
  (module `robotvision`, 위 3함수). **App.jsx 등록은 C 가 한다** — 너는 JSON 만 만들고 보고에 적어라.

## 계약 5 — tensorflow 자동 설치 (7번 항목)

**A**: TM 학습(`/api/tm/train`)이 시작될 때 tensorflow 가 없으면 **자동으로 설치**한다.
- 먼저 `python -c "import tensorflow"` 로 확인
- 없으면 `python -m pip install tensorflow` 를 돌리고 **진행 상황을 스트리밍**한다
  (기존 학습 응답이 스트리밍이면 같은 채널로, 아니면 로그로)
- 설치는 오래 걸린다(수백 MB). 시작할 때 **"AI 학습 준비물을 내려받는 중입니다. 몇 분 걸립니다"** 를 먼저 보내라
- 이미 설치돼 있으면 건너뛴다. 설치 실패 시 한국어로 이유를 돌려준다

## 계약 7 — 예제를 단계별로 나눈다 (5번 항목)

**D**: 중등·고등 예제를 **단계별 파일**로 쪼갠다. 이름 규칙:

```
m1_1_찾기.py     카메라로 보고 무엇인지 말하기까지 (로봇 없음)
m1_2_잡기.py     찾은 자리로 가서 집기까지
m1_3_놓기.py     함으로 옮겨 놓고 마무리까지 (= 지금의 완성본)
m2_1_손보기.py / m2_2_응수하기.py / m2_3_대전하기.py
```

- 각 단계는 **앞 단계를 포함**한다(누적). 학생이 그 파일 하나만 열어도 돌아간다.
- 기존 `m1_ai_sorting_blocks.py`·`m2_gesture_rps_blocks.py` 는 **지우지 말고** 최종 단계와 같게 둔다.
- 고등(`h1`~`h3`)도 같은 방식으로 3단계씩 쪼갠다.
- `src/examples/lessons.js` 에 전부 등록한다. `category` 는 지금처럼 `수업 (중등)`·`수업 (고등)` 을 쓰고,
  `title` 앞에 단계를 붙여라 — 예: `[중등 1-①] 찾기 — 무엇인지 알아보기`.
- 순서가 갤러리에서 뒤섞이지 않게 배열 순서를 단계 순으로 둔다.
